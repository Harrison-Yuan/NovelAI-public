# 神作（NovelAI）· 安装包发布面

这里是**桌面端写作工具「神作」（英文名 NovelAI）的安装包所在地**：Releases 里放每个版本的安装包与
自动更新元数据。安装产物、应用内的更新提示、这一份说明，用的都是同一个名字。
这个仓只放产物——没有源码、没有提交历史。产品的完整介绍在官网：https://www.cosvast.com

应用内的自动更新读的就是本仓的这些文件，所以它同时也是更新源。

---

## 这是什么

面向中文网文 / 长篇创作的**本地优先**桌面写作工具：一个桌面端界面，加一个**只在你这台机器上运行**的
本地服务（监听 `127.0.0.1:18888`，同一网络里别人的机器连不上它）。

稿件写在**你的磁盘上**。我们这边不存在"把正文发送到云端保存"的那条通路；服务器侧只在你登录后为了
列出你本机的作品而记录目录路径字符串，不记录里面的内容。

## 它会做什么

已实现并随安装包交付的四组能力：

- **AI 写作助手**——流式对话续写、写新章与改稿、结构与节奏分析
- **创作体系管理**——角色、伏笔、冲突与世界观一体化管理
- **大纲与思维导图**——故事弧与情节点、模板导入、可视化导图
- **本地优先存储**——作品文件存在你自己的电脑上，每一稿都留版本可追溯

桌面端右侧工具栏上你能直接点到的入口，名字就是界面上那几个字：
大纲 / 模版 / 角色 / 矛盾 / 伏笔 / 设定 / 取名 / 圈子 / 案头 / 关系。

## 你需要准备什么

- **一个 DeepSeek API key。** 这个工具走 BYOK（bring your key）：AI 调用由你本机的服务**直连厂商**，
  不经过我们的服务器。申请地址 https://platform.deepseek.com/api_keys
  ⚠️ 当前形态**只支持 DeepSeek**。代码里挂着 OpenAI 那条通路，但它的定价与实际验证没补齐，
  设置页里**故意没有**给它输入框——那不是一个"藏起来的功能"，是一个会让你失败的入口。
- **不登录也能写。** 配置 key、开作品、写稿这些本机后端都不拦你；账号（邮箱或微信登录）是给圈子
  与作品绑定那部分用的。key 只存在你本机的一个文件里，换一台电脑要重新粘贴一次。

## 选哪个包

**只需要下载一个文件。** 按你的机器选一行（文件名里的 `arm64` / `x64` 是芯片架构）：

| 你的机器 | 下载这个 | 怎么装 |
|---|---|---|
| Windows 10 / 11（64 位） | `NovelAI-Setup-<版本>-win-x64.exe` | 双击安装，可以自己挑安装目录 |
| Windows，不想装 / 拷 U 盘 | `NovelAI-Portable-<版本>-win-x64.exe` | 双击即用，不写注册表 |
| macOS · Apple 芯片（M1/M2/M3…） | `NovelAI-<版本>-mac-arm64.dmg` | 打开 dmg，把 app 拖进 Applications |
| macOS · Intel | `NovelAI-<版本>-mac-x64.dmg` | 同上 |
| Linux · Debian / Ubuntu | `NovelAI-<版本>-linux-x64.deb` | `sudo apt install ./<那个文件>` |
| Linux · 其他发行版 | `NovelAI-<版本>-linux-x64.AppImage` | `chmod +x` 之后直接运行 |

> macOS 的 `.zip` 是**应用内自动更新**的载体，不是给人手装的：手动安装请用 `.dmg`。
> 它会出现在清单里，是因为没有它 mac 上就没法自动更新。

⚠️ **关于号的历史**：Intel 芯片的 Mac 与 Linux 的包，从下一次发布起才有。
`v1.0.7` 及更早的那几发里只有 Windows x64 与 macOS Apple 芯片（arm64）——那条四平台的通路是刚并进来的，
还没有跑过一次真发布。**看某一次发布里到底有什么，以那一条 Release 自己的清单为准**，别按这张表猜。

另外这些文件请当作发布通路的一部分，**不要手工改动或删除**：

- `latest.yml` / `latest-mac.yml` / `latest-linux.yml`：自动更新要读的清单，文件名与哈希出自**同一次构建**
  （mac 那份清单里两个架构的包都在，所以 Intel 与 Apple 芯片的机器各自都收得到自己那一边的更新）
- `*.blockmap`：增量下载元数据

## 第一次打开会遇到的事

**当前这些包没有代码签名证书，属于内测包。** 后果不是"提示不好看"，是各平台会撞系统拦停：

- **Windows**：SmartScreen 报"未知发布者"，要点对**更多信息 → 仍要运行**；
- **macOS**：没有过 Apple 公证，Gatekeeper 会直接拦死——拖进 Applications 也打不开，
  要**右键 → 打开**放行一次；
- **Linux**：这一族本来就没有代码签名的通路，包是未签名的，属正常状态，不额外道歉。

每个版本的签名状态写在 Release 正文里，那几行读的是构建过程产出的读数（`SIGNING.json`），
不是这里手写的保证；证书到位之后，同一套流程会产出双击即装的包，措辞会自己改掉。

## 装完之后：你的作品在哪里

| 系统 | 数据目录 |
|---|---|
| macOS / Linux | `~/.novelai/` |
| Windows | `%LOCALAPPDATA%\.novelai\` |

里面：`projects/<作品>/`（章节正文、角色与设定、大纲、版本历史快照、AI 会话记录）、
`novelai.db`（SQLite）、`logs/`（日志）、`model_config.json`（你粘进来的 key，文件权限限定为仅本用户可读写）。

你可以随时用文件管理器复制、移动、彻底删除它们——这正是桌面形态的主要用意。
（Windows 之所以用 `LOCALAPPDATA` 而不是 `APPDATA`：后者在域策略、漫游配置或安全软件接管后
经常变成只读，实测建作品目录会被拒绝访问。）

## 哪些内容会离开你的电脑

一句实话，分三处：

1. **AI 生成时**：你让 AI 处理的那些文字——正文片段、你写的提示、被带进上下文的章节内容——
   **会离开你的电脑，送达模型厂商**（DeepSeek）。厂商如何处理这些内容受其条款约束，请在你选定的厂商侧了解。
2. **圈子（社区）里你主动发布的内容**存在云端，因为它的用途就是交流。
3. **两处由你主动点击触发的联网动作**：联网检索会把你输入的搜索词发到搜索引擎；
   模板导入会把模板编号发到对应平台的接口。它们都不会在后台自动发生。

没有广告、没有埋点统计、没有第三方跟踪脚本；崩溃报告不发往我们的服务器。
完整口径见官网的隐私政策与服务条款（页脚）。

## 自动更新

装好之后应用会自己检查这个仓的最新版本：启动后约 15 秒查一次，之后每 24 小时一次；
发现新版本先下载，**装之前会先等你本机的后端进程真的退出**再动盘上的文件——
半新半旧的安装目录比"没更新上"麻烦得多。各平台走的是：

- **Windows**：`Setup` 版走安装程序更新；`Portable` 版**不参与**自动更新，要自己回 Releases 取新版。
- **macOS**：自动更新读的是 `.zip`（所以它必须和 `.dmg` 一起发出去）；`.dmg` 只用于首次手动安装。
- **Linux**：`.AppImage` 支持应用内更新；`.deb` 跟着发行版的包管理器手动升级。

下载后可以自己核一遍校验和：macOS / Linux 用 `shasum -a 256 <文件>`，
Windows 用 `Get-FileHash <文件> -Algorithm SHA256`。每条 Release 正文里都列了本次每个文件的 sha256。

## 已知限制（我们只写今天的事实，不写"即将支持"）

- **没有导出**。docx / epub / txt 的导出实现不存在（代码里没有这条通路）。
- **没有找回密码的通路**：不发验证邮件，服务端也没有密码重置接口。忘了密码就是失去这个账号，
  请把它当成事实来保管密码。
- **没有自助导出 / 删除账号数据的入口**，也没有对外公布的受理邮箱或表单。作品数据不受这一条影响——
  它本来就在你自己的电脑上。
- **没有在线客服、工单或已公布的受理渠道**，因此不承诺响应时限。
- Intel Mac 与 Linux 的包要到下一次发布才有；Windows 与 macOS 两侧都没有代码签名（见上面两节）。

## 关于这个仓与版本号

- 这里是**发布面**。源码不在这里发布；构建用的树是源码仓的单 commit 镜像，
  **每一次 Release 的正文里都写明它对应源码仓的哪一次 commit**——想知道手上这个包是从哪棵树来的，看正文。
- 这里的 tag 由发布流水线自动创建。GitHub 的 Release 必须挂在一个**指向本仓内 commit** 的 ref 上，
  所以本仓至少要有这一颗 commit；**不要手工删这些 tag**，删掉之后下一次发布就无处可挂。
- `latest*.yml` 与 `*.blockmap` 必须由打包那一次产出（名字与哈希同源），
  所以它们没法事后手工拼——把它们删了或改了，等于改坏了别人身上的更新通路。
